# AlvaOS v0.2.0 - Storage Engine Implementation Plan

## Overview
Version 0.2.0 introduces comprehensive storage management capabilities, including disk detection, Btrfs pool management, network shares, and a file browser.

## Features Breakdown

### 1. Disk Detection & Management
**Priority: HIGH - Foundation for all storage features**

#### Backend Tasks:
- [ ] Create `/api/v1/storage/disks` endpoint
  - List all available block devices
  - Show disk size, model, serial number
  - Detect partition table type
  - Show current mount status
  - Detect if disk is part of a Btrfs pool
- [ ] Use `lsblk`, `blkid`, and `smartctl` for disk enumeration
- [ ] Filter out system disks (where OS is installed)
- [ ] Detect disk health status (SMART)

#### Frontend Tasks:
- [ ] Create `storage.html` page
- [ ] Create `storage.js` for storage management logic
- [ ] Design disk list view with cards
- [ ] Show disk status indicators (healthy, warning, critical)
- [ ] Add "Initialize Disk" button for unused disks

---

### 2. Btrfs Integration
**Priority: HIGH - Core storage functionality**

#### Backend Tasks:
- [ ] Create `/api/v1/storage/pools` endpoint (GET, POST, DELETE)
  - List existing Btrfs pools
  - Show pool capacity, usage, RAID level
  - List devices in each pool
- [ ] Create `/api/v1/storage/pools/{pool_id}/subvolumes` endpoint
  - List subvolumes in a pool
  - Create new subvolumes
  - Delete subvolumes
  - Set quotas
- [ ] Implement pool creation logic
  - Support single, RAID0, RAID1, RAID10
  - Validate disk selection
  - Format disks with Btrfs
- [ ] Implement pool expansion
  - Add devices to existing pool
  - Balance data after expansion

#### Frontend Tasks:
- [ ] Pool creation wizard
  - Disk selection interface
  - RAID level selector
  - Pool name input
  - Confirmation dialog
- [ ] Pool management view
  - Show pool details (capacity, usage, RAID level)
  - List devices in pool
  - Show subvolumes
  - Add disk to pool button
- [ ] Subvolume management
  - Create subvolume dialog
  - Delete subvolume with confirmation
  - Show subvolume tree structure

---

### 3. Network Shares (NFS/SMB)

#### Backend Tasks:
- [ ] Create `/api/v1/storage/shares` endpoint (GET, POST, PUT, DELETE)

#### Frontend Tasks:
- [ ] Share creation wizard
  - Path selector (browse subvolumes)
  - Protocol selector (NFS/SMB)
  - Access control settings
  - Guest access toggle
- [ ] Share list view
  - Show protocol, path, status
  - Edit/Delete buttons
  - Connection instructions
- [ ] Share settings dialog
  - Permissions configuration

## Technical Dependencies

### System Packages Required:
```bash
apt-get install -y \
    btrfs-progs \
    smartmontools \
    nfs-kernel-server \
    samba \
    samba-common-bin
```

### Python Packages Required:
```python
# Add to requirements.txt
pyudev>=0.24.0  # For disk detection
```

### Permissions Required:
- Backend needs sudo access for:
  - `lsblk`, `blkid`
  - `mkfs.btrfs`
  - `btrfs` commands
  - `smartctl`
  - Editing `/etc/exports` and `/etc/samba/smb.conf`
  - Service restarts

---

## Database/State Management

For v0.2.0, we'll continue using file-based storage:
- Pool configurations: `/var/lib/alvaos/pools.json`
- Share configurations: `/var/lib/alvaos/shares.json`
- SMART history: `/var/lib/alvaos/smart_history.json`

---

## Security Considerations

1. **Disk Operations**: Require confirmation for destructive operations
2. **Path Validation**: Prevent path traversal in file browser
3. **Share Access**: Default to restrictive permissions
4. **SMART Data**: Read-only, no security concerns
5. **Pool Creation**: Warn about data loss on disk initialization
