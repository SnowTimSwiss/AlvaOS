# Contributing to AlvaOS

Join us in making self-hosting simple, stable, and transparent.

## Philosophy
- **Stability first**: Conservative tech over cutting-edge features.
- **Simplicity**: Avoid overengineering; keep code "boring" and explicit.
- **Transparent**: No "magic" or hidden telemetry.

## Getting Started
1. **Explore**: Review [STRUCTURE.md](STRUCTURE.md), the [ROADMAP.md](ROADMAP.md), and the project [README.md](/README.md).
2. **Setup**: Fork the repo and pick an area: Backend, Frontend, Installer/Scripts, or Docs.
3. **Workflow**: Branch → Code+Test → Pull Request (PR).

## Guidelines
- **General**: Clear names, explicit error handling, and idempotent scripts.
- **Backend**: Log operations and add unit tests for logic.
- **Frontend**: Responsive, reusable components; test in light/dark modes.
- **Docs**: Simple, up-to-date language with examples.

## Testing & Support
- **Current**: Manual verification during early dev.
- **Questions**: Open an issue for bugs or start a discussion for ideas.
